# 场景路由表

> **本文件是权威源。** 同目录的 `场景路由.yaml` 是机器可读副本。修改场景定义时先改本文件，再同步 .yaml。
>
> **SOP-01 是硬门禁。** Agent 必须先完成环境检测 + Skill/插件自动安装，门禁判断 🟢 放行后，才进入本路由表的场景检测。
>
> Agent 在 SOP-01 装机完成后，根据输入材料自动检测场景，裁剪流程。
> 用户也可显式触发指定场景。

## 场景D：原型+数据重构页面

### 典型特征

- 输入：PNG/JPG 原型截图 + 多个 Excel/CSV 数据文件
- 输出：完整的数据可视化页面（HTML/CSS/JS 或 React 组件）
- 技术栈：Chart.js/ECharts + CSS Grid/Flex + 数据绑定
- 不需要：后端 API、数据库、需求文档

### 特有阶段增强

**SOP-02 替代：原型+数据理解**

1. 读取原型图（多模态 LLM 直接读图 或 通过 MCP 工具比如 qclaw-text-file 读取剪贴板图片）
2. 识别布局结构：Grid 分区（几行几列）、卡片/面板/图表位置
3. 识别数据源：Excel 文件名 → 字段名 → 与图表/面板的对应关系
4. 识别色值/字体/间距：从原型中提取视觉参数，写入 tokens 或 CSS 变量
5. 输出"布局-数据映射表"

**SOP-04 替代：数据处理**

1. 读取 Excel/CSV 文件（Python pandas 或 Node.js xlsx 库）
2. 统计聚合：按维度（时间/区域/类型）做 count/sum/avg
3. 输出处理后的 JSON 数据文件，供前端组件直接消费
4. 写入 `coding-assistant/tools/03_接口契约/`（用 JSON 替代 API 契约，作为"数据契约"）

**SOP-06 编码增强**

- 先用纯 HTML/CSS 验证布局和视觉（与原型 1:1 对照）
- 确认布局无误后再接入真实数据和图表
- 图表与数据来自上一步的 JSON，不硬编码

### 参考案例

> 案例来源：`案例场景_基于原型+数据重构大屏页面_v1.0.docx`
>
> - 输入：1 个 PNG 原型 + 7 个 Excel（巡护/事件/设备/人员/审批等）
> - 工具链：LLM 多模态 → 识别原型布局 → Python pandas 处理 Excel → Chart.js 渲染
> - 产出：806 行 HTML，60KB，Dashboard 含 3 列 Grid + Canvas 图表 + overlay 面板
> - 耗时：2.5h（传统 6~8 工作日），效率提升 65~70%

## 场景E：设计稿→全栈一条龙

### 典型特征

- 输入：一张架构图/设计稿（含实体、关系、流程）
- 输出：DDL + Domain + Mapper + Service + Controller + OpenAPI 契约
- 技术栈：Java/Spring Boot + PostgreSQL/PostGIS
- 不需要：需求文档（图即需求）、前端代码

### 特有阶段增强

**SOP-02 替代：设计稿理解 + 项目探索**

1. 读取设计稿（多模态 LLM 直接读图）
2. 提取实体（表名/字段/类型/关系）
3. 提取流程（状态机/工作流/审批链）
4. 提取接口（读图上的 API 标注）
5. 使用 explore agent 理解项目现有代码结构和命名约定

**SOP-03 简化：仅架构确认**

- 不生成完整技术方案文档
- 只输出"实体-关系图" + "模块划分" + "关键决策"三项
- 人确认实体关系正确即可

**SOP-04 增强：DDL + Domain + OpenAPI 三连生成**

按顺序串联生成（后一步依赖前一步）：
```
Step 1: DDL 生成
  输出：*.sql 文件（PostgreSQL + PostGIS）
  内容：CREATE TABLE + GIST 索引 + 注释

Step 2: Domain 生成
  输入：DDL
  输出：Java Entity 类（Lombok @Data + @Schema description + Jackson 日期注解）
  内容：字段映射、GEOMETRY → String（GeoJSON）

Step 3: Mapper 生成
  输入：Domain + DDL
  输出：Mapper XML（resultMap + CRUD SQL + ST_AsGeoJSON() 空间查询）

Step 4: Service 生成
  输入：Mapper + 流程规则
  输出：Service 类（CRUD + 工作流状态转移 + 查询条件构建）

Step 5: Controller + OpenAPI 生成
  输入：Service 方法签名
  输出：REST Controller（@Tag/@RequestMapping/@Operation）+ OpenAPI 3.0 yaml
```

**SOP-06 编码增强**

- 每步"生成 → tsc/编译验证 → 人审"循环
- DDL 先在数据库跑一遍确认无语法错误
- Domain 编译通过后再生成 Mapper
- workflow 状态转移规则先让业务方确认再生成 Service

### 参考案例

> 案例来源：`案例场景_OpenCode 参照一张图设计稿 → 流程逻辑+模块+建库一条龙_v1.0.docx`
>
> - 输入：1 张架构设计图（含 6+ 模块、实体、流程）
> - 工具链：OpenCode explore agent → 项目探索 → AI 提取实体 → DDL 生成 → Domain → Mapper → Service → Controller → OpenAPI
> - 产出：8 张表 SQL、15 Domain、30+ Mapper XML、14 Service、22 Controller、OpenAPI 3.0 spec，~21000 行，180+ 文件
> - 耗时：5 天 → 2 天，效率提升 60%，API 文档覆盖率 ~100%

## 场景检测规则

Agent 根据以下信号自动判断场景：

### 优先级一：用户显式触发

| 用户说 | 判为 |
|--------|------|
| "大屏""数据可视化""重构页面""Dashboard" | **D** |
| "一条龙""全栈生成""建库""从图到代码" | **E** |
| "从零""从0""新功能""开发一个" | A（待分子类型） |
| "前端""设计稿转代码""Figma""页面" | **A-前端** |
| "后端""API 开发""服务端" | **A-后端** |
| "接口生成""契约""OpenAPI""api.md" | C |

### 优先级二：输入材料特征

| coding-assistant/tools/01_需求输入/ 中有什么 | 倾向 |
|-----------------------|------|
| PNG/JPG 原型 + Excel/CSV 数据（3+ 文件）| **D** |
| 单张架构图/设计稿 + 无其他材料 | **E** |
| 需求文档 + 数据样例 + 原型 三件齐 | A（待分子类型） |
| Figma/设计稿 + API 文档 | **A-前端** |
| 需求文档 + 数据样例（无设计稿/原型）| **A-后端** |
| OpenAPI yaml / Swagger / api.md | C |

### 优先级三：项目配置

| coding-assistant/tools/00_项目配置/项目信息.md | 倾向 |
|------------------------|------|
| 架构形态：分离 + 技术栈含 Java/PostgreSQL | E |
| 项目端型：前端 | A-前端 |
| 项目端型：后端 | A-后端 |
| 项目端型：全栈 | A-全栈 |
| `src/` 已有大量代码 | C/D（非从零） |

### 场景 A 子类型判定

> 判定场景为 A 后，继续判定子类型。优先自动检测，无法确定时使用 `AskUserQuestion`。

```
场景 A 已判定 → 判定子类型

Step 1: 用户触发语含关键词？
  → "前端""设计稿""Figma""页面" → A-前端
  → "后端""API""服务端" → A-后端
  → "全栈""一条龙" → A-全栈
  → 无明确关键词 → Step 2

Step 2: 输入材料特征？
  → Figma/设计稿 + API 文档 → A-前端
  → 需求文档 + 无设计稿 + 项目端型=后端 → A-后端
  → 需求+数据+原型三件齐 + 项目端型=全栈 → A-全栈
  → 不确定 → Step 3

Step 3: 项目配置端型？
  → 前端 → A-前端
  → 后端 → A-后端
  → 全栈 → A-全栈
  → 未填写 → Step 4

Step 4: AskUserQuestion 让用户选择
  问题: 判定为场景 A（从0到1），请确认子类型？
    [A] 全栈 — 前后端都写，走完整 10 阶段
    [B] 前端 — 仅前端页面，有 API 文档
    [C] 后端 — 仅后端服务，有需求文档
```

### 决策流程

```
coding-assistant/tools/01_需求输入/ 有实际输入文件（非 放入说明.md）？
  → 否：Agent 使用 AskUserQuestion 让用户选择
    → [A] 我自行放入 → 暂停，等待用户 → 用户回来后再次 AskUserQuestion
        → [A] 文件已放入，继续 → 检查目录 → 继续流程
        → [B] 改为对话生成 → 逐项询问 → 生成需求文件
    → [B] 对话生成 → 逐项询问 → 生成需求文件
  → 是：继续检测场景

用户触发了关键词？
  → 是：按用户指定（A 继续判定子类型）
  → 否：检查输入材料
    → Excel+原型图 → D
    → 单张架构图 + Java/Spring → E
    → 设计稿+API文档 → A-前端
    → 需求+数据（无设计稿）→ A-后端 或 A-全栈（看项目端型）
    → 需求+数据+原型三件齐 → A-全栈
    → OpenAPI/Swagger → C
    → 无法判断 → 列出依据，让用户二选一确认
```
