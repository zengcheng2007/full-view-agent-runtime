# SOP-09 · 联调

## 说明
一体化场景几乎不需要联调；分离架构 / 跨模块出错时执行本阶段。

**本阶段为非必须**——仅分离架构或跨模块协作时触发。

---

## 前置条件
- SOP-08 走查通过
- 分离架构前后端代码已部署到联调环境

---

## 环境预检（自动执行）

> Agent 进入本阶段前，先快速验证联调环境是否可达。不可达 → 告知用户，不浪费调试时间。

| 检查项 | 命令/方法 | 通过判据 |
|--------|---------|---------|
| 前端 dev server 运行中 | `curl -s -o /dev/null -w "%{http_code}" http://localhost:5173` | 返回 200 |
| 后端服务可达 | `curl -s -o /dev/null -w "%{http_code}" http://localhost:8000/actuator/health` 或读 `.env.development` 中的 `VUE_APP_API_BASE` | 返回 200 |
| 最近改动可回滚 | `git log --oneline -3` | 有 commit 记录 |

> 任一项不通过 → 报告用户，询问是否已部署联调环境。不自动进入调试。

---

## 输入

> Agent 执行本阶段前，必须先验证以下文件是否存在。
> **输入缺失时，不可直接终止流程。**

| # | 读取路径 | 用途 | 适用场景 | 来源阶段 |
|---|---------|------|---------|---------|
| 1 | `coding-assistant/tools/07_走查记录/走查报告-[日期].md` | 走查结论和遗留问题 | A分离, E分离 | SOP-08 |
| 2 | `coding-assistant/tools/03_接口契约/api.md` 或 `coding-assistant/tools/03_接口契约/openapi.yaml` | 接口字段对照 | A分离, E分离 | SOP-04 |

**输入缺失处理：** 走查报告不存在时，Agent 使用 `AskUserQuestion`：

```
问题: 走查报告未就绪，无法确认代码质量基线，如何处理？
  [A] 回到 SOP-08 走查 — 完成走查带着报告再来
  [B] 跳过走查直接联调 — 跳过走查检查，直接验证接口连通性（标记为"未走查"）
```

> **场景差异**：仅分离架构触发（A-全栈 分离 / A-后端 分离 / E 分离）。A-前端 / C / D 跳过本阶段。一体化架构不触发联调。

---

## 四阶段调试

套用 `coding-assistant/prompts/P-C-7-联调调试.md`，激活 skill `Use the systematic-debugging skill`：

| 阶段 | 动作 | 目标 |
|---|---|---|
| 1 根因调查 | 读错误信息 / 复现 / 看最近改动 / 加诊断日志 | 找出 WHAT 和 WHY |
| 2 模式分析 | 找类似的工作示例对比 | 列差异 |
| 3 假设验证 | 一次只改一个变量 | 验证或推翻 |
| 4 实施修复 | 写回归测试 → 修复 → 跑通 | 根因修复，不打补丁 |

---

## 核心铁律

> ★ **3 次失败质疑架构**——同一问题改 3 次没修好，停下来重新设计，不要 fix #4。

---

## 执行步骤

1. 收集联调环境的错误信息和日志
2. 激活 skill：`Use the systematic-debugging skill`
3. 按四阶段逐步执行
4. 记录调试过程到 `coding-assistant/tools/08_联调记录/联调记录-[日期].md`
5. 每次修复后 fresh 跑全量测试

---

## 联调检查清单

- [ ] 所有接口请求/响应格式正确
- [ ] 异常路径：超时/网络错误/500 有降级处理
- [ ] 字段类型对齐（snake_case ↔ camelCase 转换正确）
- [ ] 认证/鉴权流程正常
