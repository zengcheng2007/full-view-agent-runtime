# SOP-02 · 需求吃透

## 目标
拿到需求后**不动代码**，先确认三件输入齐全：需求清单、真实数据样例、设计/原型链接。

---

## 前置条件
- SOP-01 装机检查通过
- `coding-assistant/tools/01_需求输入/` 有需求材料

---

## 输入

> Agent 执行本阶段前，必须先读取以下文件。不存在则停止，告知用户缺失项。

| # | 读取路径 | 用途 | 适用场景 | 来源阶段 |
|---|---------|------|---------|---------|
| 1 | `coding-assistant/tools/01_需求输入/` 下所有文件 | 需求清单、数据样例、设计/原型 | A, E | 人工放入 |
| 2 | `coding-assistant/tools/00_项目配置/项目信息.md` | 技术栈、架构形态、关键约束 | A, E | SOP-01 |

> **场景差异**：C/D 跳过本阶段。A-前端 走简化需求吃透，A-全栈/A-后端 走完整需求吃透。D 的"原型+数据理解"替代需求吃透，见 `coding-assistant/sop/场景路由表.md`。

---

## 输入接口判据

| 输入项 | 判据 | 没到位怎么办 |
|---|---|---|
| 需求清单 | 含场景 / 用户 / 核心指标 / 交互需求 | 使用 `AskUserQuestion` 工具让用户选择：[A] 自行补充后继续 / [B] Agent 对话引导生成 |
| 真实数据样例 | DB 样本 / Excel / 字段口径 / 第三方 API 文档 | 同上：[A] 自行补充 / [B] 对话引导生成字段口径描述 |
| 设计 / 原型 | 可点开能跑 | 同上：[A] 自行补充链接或截图 / [B] 对话描述，生成设计说明，标注"无原型，以文字描述为准" / [C] 若已提供设计稿**链接**(非截图)，可走「设计稿 MCP 读取分支」由 Agent 自动读取并生成/完善需求文档 |

> ★ **没说清楚不接活**——这是编码阶段唯一硬规矩。AI 也救不了糊活。

---

## 执行步骤

1. 读取 `coding-assistant/tools/01_需求输入/` 下所有文件
2. 对照输入接口判据，标注已有 ✅ / 缺失 ❌ / 不完整 ⚠️
3. **如发现设计稿链接（非截图），询问用户是否启用「设计稿 MCP 读取分支」**（见下节）
4. 套用 `coding-assistant/prompts/P-C-1-需求理解.md` 分析需求（MCP 已读取时，整合 MCP 数据再分析）
5. 输出需求理解报告（含不确定点清单）
6. 不完整的需求要素标记为【待确认】
7. 如三件输入之一完全缺失，使用 `AskUserQuestion` 工具让用户选择 [A] 自行补充 / [B] Agent 对话引导生成

## 设计稿 MCP 读取分支（可选）

> **触发条件**：用户在 `coding-assistant/tools/01_需求输入/` 提供了设计稿**链接**(非本地截图),无论场景是 A-全栈 / A-前端 / E,均可启用本分支让 Agent 通过 MCP 直读设计稿,**生成或完善需求文档**。
>
> 与 [SOP-06 场景 A-前端 预编码门禁](SOP-06-编码.md#场景-a-前端-预编码门禁) 区别:本分支在需求吃透阶段触发,目的是**用设计稿元数据补充需求理解**(页面清单 / 字段 / 交互);SOP-06 的 P-C-B 在编码前触发,目的是**用设计稿 token / 组件树指导代码生成**。两者可同链接复用,但解析侧重不同。

### 触发流程

```
Step 1: 询问是否通过 MCP 服务读取设计稿链接?
   ├─ 是 → Step 2
   └─ 否 → 跳过本分支,按用户提供的链接或截图常规处理需求

Step 2: 识别设计稿平台 + 检测对应 MCP 是否已安装 (claude mcp list)
   ├─ MCP 已装 → Step 4
   ├─ MCP 未装但存在 → Step 3
   └─ 平台无 MCP → 告知用户,跳过本分支(按链接/截图常规处理)

Step 3: 询问是否安装 MCP?
   ├─ 安装 → 执行安装命令 → 提示重启 Claude Code → 等用户回"继续" → Step 4
   └─ 跳过 → 退出本分支,按链接/截图常规处理

Step 4: 用户授权,Agent 调用 MCP 读取设计稿
        → 提取页面清单 / 字段 / 交互 / tokens
        → 输出"设计稿解析报告"
        → Step 5

Step 5: 整合 MCP 数据生成/完善需求文档
        → P-C-1 分析时把 MCP 数据作为补充输入
        → 在"需求理解报告"中标注哪些点来自设计稿 MCP
```

### Step 1 · 询问启用 MCP

Agent 检测到 `coding-assistant/tools/01_需求输入/` 含设计稿链接(URL 形式,非本地 PNG/JPG)时,使用 `AskUserQuestion`:

```
问题: 检测到设计稿链接 [URL]。是否通过 MCP 服务读取设计稿来生成/完善需求文档?
  [A] 是,通过 MCP 读取 — 我会识别平台并检测对应 MCP
  [B] 否,按链接信息常规分析 — 仅记录链接,需求由用户描述补充
```

- 用户选 [A] → 进入 Step 2
- 用户选 [B] → 退出本分支,回到 SOP-02 主流程第 4 步(P-C-1 常规分析)

### Step 2 · 识别平台 + 检测 MCP

Agent 解析链接域名匹配平台(对应表见 [P-C-B-设计稿读取确认.md §支持的设计稿平台与 MCP 对应表](../prompts/P-C-B-设计稿读取确认.md#支持的设计稿平台与-mcp-对应表)):

| 平台 | 识别特征 | 对应 MCP |
|------|---------|---------|
| Calicat | `*.calicat.*` | `calicat`(本工程内置) |
| MasterGo | `mastergo.com` | `mastergo` |
| Figma | `figma.com/file/*` 或 `figma.com/design/*` | `figma-developer-mcp` / `figma-context-mcp` |
| Sketch / Pixso | `.sketch` / `pixso.*` | 暂无成熟 MCP |

执行 `claude mcp list` 检测对应 MCP:

```
🔍 MCP 检测结果:
   - 识别平台:[X]
   - 对应 MCP:[Y]
   - 已装状态:[已装 / 未装 / 平台无 MCP]
```

**分支:**
- 已装 → 跳 Step 4
- 未装但存在 → Step 3
- 平台无 MCP → 告知用户"该平台暂无 MCP 可用,无法自动读取,本分支退出,按链接信息常规分析",回到 SOP-02 主流程

### Step 3 · 询问安装 MCP

使用 `AskUserQuestion`:

```
问题: 检测到 [平台] 对应的 [MCP 名称] 未安装,是否安装?
  [A] 安装 — 执行 [安装命令],安装后需重启 Claude Code
  [B] 跳过,按链接常规分析 — 不读 MCP,需求由用户口述补充
```

- 用户选 [A]:
  1. Agent 执行 `claude mcp add <name> <args>`(实际参数以官方文档或用户提供为准,**不可猜测**)
  2. 安装完成后告知:"MCP 已安装,**请重启 Claude Code 加载 MCP**,重启后回到本流程说'继续'"
  3. 更新 [当前状态.md](../tools/99_运行日志/当前状态.md):`阶段状态 = 等待人工`
  4. 停止推进,等用户重启后说"继续",进入 Step 4
- 用户选 [B] → 退出本分支

### Step 4 · 授权并读取设计稿

Agent 提示用户授权 MCP(首次调用弹窗,选"Yes, and don't ask again"永久授权)。

调用 MCP 工具读取(以本工程内置 `calicat` MCP 为例):

| 调用目标 | MCP 工具 | 提取内容 |
|---------|---------|---------|
| 文件元信息 | `get_meta_data` | 设计稿标题 / 创建者 / 页面总数 |
| 页面/图层结构 | `get_design_data` | 页面清单 / 模块划分 / 关键组件 |
| 交互稿数据 | `get_interaction_design_data` | 跳转关系 / 状态切换 / 用户流 |
| 关键截图 | `get_screenshots` | 每页缩略图(供需求文档引用) |

将解析结果写入 [设计稿解析-[日期].md](../tools/01_需求输入/):

```markdown
# 设计稿解析报告 (来源: MCP 读取)

## 元信息
- 平台: [Calicat / MasterGo / Figma]
- 文件 ID: [...]
- 设计稿标题: [...]
- 页面总数: [N]

## 页面清单
| # | 页面名 | 用户角色 | 核心操作 | 涉及字段 |
|---|--------|---------|---------|---------|
| 1 | 登录页 | 全部 | 输入手机号+验证码 | phone, code |

## 交互流
[从 get_interaction_design_data 提取的页面跳转关系]

## 截图引用
- 页面 1: ![](screenshots/page-1.png)
- ...

## 不确定项
[MCP 数据中无法确定的业务规则,需用户确认]
```

### Step 5 · 整合 MCP 数据生成/完善需求文档

Agent 套用 [P-C-1-需求理解.md](../prompts/P-C-1-需求理解.md),把 MCP 解析数据作为补充输入(详见 P-C-1 「MCP 设计稿数据整合」段)。

**关键产出:**
- 用户**已有需求文档** → 用 MCP 数据**完善**:补全页面清单 / 字段表 / 交互细节,标注"补充自设计稿 MCP"
- 用户**无需求文档** → 用 MCP 数据**生成**初版:页面 → 用户角色 → 核心操作 → 字段,作为需求草稿
- 生成后必须由用户确认业务规则(MCP 看不到业务约束,如"手机号唯一性""支付失败回滚")

需求文档输出仍走 SOP-02 标准路径 → [需求理解报告.md](../tools/01_需求输入/需求理解报告.md),在「输入材料检查」表的"设计/原型"行标注**来源 = MCP 读取**。
