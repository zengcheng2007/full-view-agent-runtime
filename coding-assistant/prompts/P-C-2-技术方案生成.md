SOP-03 技术方案

## 使用时机
SOP-02 需求吃透完成，需求理解报告已出。

---

## Prompt 模板

```
Use the writing-plans skill.

需求理解：[粘贴 P-C-1 输出]

技术约束：
- 前端：[框架/UI库/图表库/地图库]
- 后端：[框架/数据库/缓存]
- 架构形态：[一体化 / 分离]
- 必须支持：[QPS / 数据量 / 兼容性 等约束]
- 样式铁律：色值/间距/圆角/字号必须 import from '@/tokens'

关键约束：
- [从 coding-assistant/tools/00_项目配置/项目信息.md 获取]
- 禁用 any 类型
- 状态管理：[Zustand/Vuex/Redux]

请输出完整技术方案，包括：

1. **数据流**
   - 用户操作 → 前端组件 → API/函数调用 → 数据处理 → 响应 → UI 更新
   - 标注每个环节涉及的具体文件/模块

2. **接口设计草案**
   - [一体化] 列出所有新增/修改的函数签名（参数类型 + 返回类型）
   - [分离架构] 列出所有 API 端点（方法 + 路径 + 请求体 + 响应体 + 错误码）

3. **关键技术决策**
   - 用表格列出每个决策的选项 A/B、选择、理由
   - 涉及状态管理、数据获取、组件复用、性能优化等

4. **风险点**
   - 用表格列出每个风险的概率、影响、缓解措施
   - 至少覆盖：性能、安全、兼容性、第三方依赖

5. **任务拆分草案**
   - 按业务闭环列出大致步骤
   - 每步涉及的文件范围

输出到 coding-assistant/tools/02_技术方案/技术方案-[日期]-[feature].md
```

---

## 质量要求

- 关键决策有对比选项和理由，不写"显然""当然"
- 风险标注概率（高/中/低）和影响（高/中/低）
- 接口字段含类型，不写"等""略"
- 方案生成后**必须停下来**等人工审核
