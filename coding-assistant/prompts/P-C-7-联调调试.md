# P-C-7 · 联调调试

## 触发阶段
SOP-09 联调（非必须，仅分离架构/跨模块时使用）

## 使用时机
联调环境出错时。

---

## Prompt 模板

```
Use the systematic-debugging skill.

联调问题描述：

[错误信息 / 异常行为描述]

环境信息：
- 前端：http://localhost:5173
- 后端：http://localhost:8000
- 最近改动：[git log --oneline -5]

---

## 阶段 1：根因调查

读错误信息、复现问题、看最近改动、加诊断日志。
目标：找出 WHAT 和 WHY。

回答以下问题：
1. 错误出现在哪个环节（前端/后端/网络）？
2. 请求是否到达后端？响应是什么？
3. 最近改了什么相关代码？

## 阶段 2：模式分析

找类似的工作示例对比。
回答以下问题：
1. 有没有类似的接口正常工作？
2. 差异在哪里（请求格式/字段名/认证方式）？

## 阶段 3：假设验证

一次只改一个变量，验证或推翻假设。
列出每个假设和验证结果。

## 阶段 4：实施修复

写回归测试 → 修复 → 跑通。
修复后 fresh 跑全量测试确认无回归。

---

约束：
- 同一错误改 3 次没修好 → 停下来重新设计，不打补丁
- 每次修复后 fresh 跑全量测试
- 修复记录写入 coding-assistant/tools/08_联调记录/联调记录-[日期].md
```

---

## 输出格式

按四阶段分别输出调查结论：

```
## 阶段 1：根因调查
- 错误位置：[前端/后端/网络]
- 根因：[具体原因]
- 证据：[日志/响应/截图]

## 阶段 2：模式分析
- 对比示例：[正常工作的接口]
- 差异点：[列出]

## 阶段 3：假设验证
- 假设 1：[假设] → [验证结果]
- 假设 2：[假设] → [验证结果]

## 阶段 4：实施修复
- 修复内容：[具体改动]
- 回归测试：[测试结果]
```
