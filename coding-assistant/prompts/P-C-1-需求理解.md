# P-C-1 · 需求理解

## 触发阶段
SOP-02 需求吃透

## 使用时机
读取完 `coding-assistant/tools/01_需求输入/` 下所有材料后，套用此 Prompt 分析需求。

---

## Prompt 模板

```
我要做这个需求：

[粘贴需求清单/需求文档]

数据资料：

[粘贴数据样例 / 字段口径 / API 文档]

设计 / 原型：

[粘贴链接或截图。如已通过 SOP-02 设计稿 MCP 读取分支生成 `coding-assistant/tools/01_需求输入/设计稿解析-[日期].md`，引用该文件路径]

项目信息：
- 技术栈：[从 coding-assistant/tools/00_项目配置/项目信息.md 获取]
- 架构形态：[一体化 / 分离]
- 关键约束：[从项目信息获取]

请你完成以下任务（不要写代码）：

1. **需求理解**
   - 用 2-3 句话概括核心目标
   - 列出涉及的用户角色和核心场景
   - 列出关键业务指标（如有）

2. **输入材料评估**
   - 需求清单：是否完整，缺什么
   - 数据样例：字段口径是否清晰，有无歧义
   - 设计/原型：是否可交互，覆盖所有场景了吗

3. **不确定点清单**
   - 列出你看到的所有不确定点（字段含义、业务规则、边界条件）
   - 每个不确定点标注风险等级（高：阻塞编码 / 中：影响质量 / 低：可先写后确认）

4. **技术关注点**
   - 涉及哪些已有模块/组件
   - 有没有明显的性能风险、安全风险、兼容性风险

5. **下一步建议**
   - 可以进入技术方案阶段，还是需要补充材料
```

---

## MCP 设计稿数据整合（可选）

> 仅在 SOP-02「设计稿 MCP 读取分支」已生成 `设计稿解析-[日期].md` 时启用。

启用条件下，Agent 在执行上述 5 项任务前，先读取 `coding-assistant/tools/01_需求输入/设计稿解析-[日期].md`，按以下规则整合：

### 整合规则

| 用户输入状态 | MCP 数据角色 | Agent 行为 |
|-------------|------------|-----------|
| 用户**已有**完整需求文档 | 补充对照 | 用 MCP 数据**完善**：补全用户角色 / 页面清单 / 字段表 / 交互细节；标注"补充自设计稿 MCP" |
| 用户**部分**需求文档（如只有概要） | 扩写依据 | 用 MCP 的页面/字段数据**扩写**用户提供的概要，标注扩写来源 |
| 用户**无**需求文档 | 主要依据 | 用 MCP 数据**生成需求草稿**：页面 → 用户角色 → 核心操作 → 字段；明确标注"需求草稿来源：设计稿 MCP，业务规则待用户确认" |

### 标注要求

需求理解报告中,**所有来自 MCP 的内容必须标注来源**,便于人工审核区分:

```markdown
## 输入材料检查
| 输入项 | 状态 | 来源 |
|--------|------|------|
| 需求清单 | ✅ | 用户提供 + MCP 补充(页面 3、5、7) |
| 数据样例 | ⚠️ | 用户提供字段口径，MCP 提供字段名 |
| 设计/原型 | ✅ | MCP 读取(Calicat/MasterGo/Figma) |
```

### 注意事项

- MCP **看不到业务规则**(如"手机号唯一""支付失败回滚")——这些必须由用户确认,不可由 Agent 从设计稿推测
- MCP 数据中的字段名/类型仅作参考,**最终以接口契约(SOP-04)为准**
- 设计稿可能与最新需求有版本差,生成的需求草稿要在第 5 项"下一步建议"中标注"待与产品/设计确认版本一致"
- MCP 读取失败或数据残缺时,降级到截图/链接常规分析,不要硬编造

---

## 输出

> 完成分析后，将结果写入 `coding-assistant/tools/01_需求输入/需求理解报告.md`（参照 `coding-assistant/sop/SOP-02-需求吃透.md` 的输出格式模板），同时向用户汇报。
>
> 写入内容包括：需求理解、输入材料评估表、不确定点清单（含风险等级和确认方式）、技术关注点、阶段判断。

---

## 红线

- 此阶段**禁止写代码**
- 不确定点不猜测、不自行补全
- 不完整的输入不接活
