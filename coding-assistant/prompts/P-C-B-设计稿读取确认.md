# P-C-B · 设计稿读取确认(场景 A-前端 专用)

## 触发阶段
SOP-06 编码 · 场景 A-前端(从0到1 · 前端)预编码阶段

## 使用时机
场景判定为 A-前端、进入 SOP-06 编码前,**必须先完成设计稿源确认 6 步**。其余场景/子类型不触发本 Prompt。

---

## 设计目的

场景 A-前端 的核心输入是设计稿,代码生成的精度取决于设计稿源的可读性:
- **MCP 直读** → 精确还原 token、间距、组件结构,代码质量高
- **截图参照** → 仅能视觉对照,色值/间距/层级靠肉眼推断,代码质量中等

在动手写代码前显式确认数据源,避免事后返工。

---

## 支持的设计稿平台与 MCP 对应表

> Agent 按用户提供的链接 / 文件类型识别平台,匹配下表查询 MCP 可用性。

| 平台 | 域名/特征 | 对应 MCP | 安装命令(参考) |
|------|----------|---------|---------------|
| Calicat | `*.calicat.*` / `*.calicat.ai` | `calicat` MCP(本工程已内置工具集) | 已内置,无需安装 |
| MasterGo | `mastergo.com` / `*.mastergo.com` | `mastergo` MCP | `claude mcp add mastergo <参数>` |
| Figma | `figma.com/file/*` / `figma.com/design/*` | `figma-developer-mcp` 或 `figma-context-mcp` | `claude mcp add figma <参数>` |
| Sketch | `.sketch` 本地文件 | 暂无成熟 MCP(2026-05 时点) | — |
| Pixso | `pixso.cn` / `pixso.net` | 暂无官方 MCP(2026-05 时点) | — |

> ⚠️ MCP 生态变化快,Agent 执行前应先用 `claude mcp list` 列出当前已装 MCP,再判断是否需要新增安装。MCP 命名/参数以官方文档为准,本表仅作匹配参考。

## 6 步交互流程

> Agent 严格按顺序执行,每步使用 `AskUserQuestion` 工具与用户交互,不可跳步、不可猜测。

### Step 1 · 确认设计稿链接是否存在

使用 `AskUserQuestion`:

```
问题: 是否有前端原型设计稿链接?
  [A] 有链接 — 我会提供完整可访问的设计稿 URL
  [B] 只有截图 — 我只能提供 PNG/JPG 截图,无在线链接
  [C] 都没有 — 仅有文字描述或需求文档
```

**分支:**
- 用户选 [A] → 进入 Step 2
- 用户选 [B] → **跳到 Step 6**(截图参照模式)
- 用户选 [C] → 终止本流程,告知用户:"场景 A-前端 必须有设计稿输入,请补充链接/截图后再进入编码。建议返回 SOP-02 补充设计输入,或切换为场景 A-全栈 走完整需求吃透流程。"

---

### Step 2 · 识别设计稿平台类型

请用户粘贴设计稿链接后,Agent 解析域名匹配平台:

```
请粘贴完整的设计稿链接(含 file_id / node_id 等参数)。
```

收到链接后,Agent 自动识别:

```
✅ 已识别平台:[Calicat / MasterGo / Figma / Sketch / Pixso / 未知]
   链接:[完整 URL]
   文件 ID:[解析出的 ID,如有]
```

如无法识别,使用 `AskUserQuestion`:

```
问题: 无法从链接自动识别设计稿平台,请确认类型?
  [A] Calicat
  [B] MasterGo
  [C] Figma
  [D] 其他(Sketch / Pixso / 自研平台)
```

---

### Step 3 · 查询 MCP 可用性

Agent 执行 `claude mcp list`,与本 Prompt §支持平台对应表比对:

```
🔍 MCP 可用性检查:
   - 当前已装 MCP:[列出]
   - 匹配平台 [X] 的 MCP:[已装 / 未装 / 平台暂无 MCP]
```

**分支判断:**
- 平台对应 MCP **已安装** → 跳到 Step 5(授权读取)
- 平台对应 MCP **未安装但存在** → 进入 Step 4(询问是否安装)
- 平台对应 MCP **不存在**(Sketch/Pixso 等) → 跳到 Step 6(截图参照模式),并告知用户:"该平台暂无可用 MCP,建议导出关键页面截图作为输入。"

---

### Step 4 · 询问安装 MCP

使用 `AskUserQuestion`:

```
问题: 检测到 [平台名] 对应 MCP 未安装,是否安装?
  [A] 安装 — 执行 [安装命令],安装后由我授权使用
  [B] 跳过,改用截图参照模式 — 我提供截图,Agent 按截图生成代码
```

**分支:**
- 用户选 [A]:
  1. Agent 执行安装命令(如 `claude mcp add <name> <args>`),实际命令参数应由用户提供或参考官方文档
  2. 安装完成后告知用户:"MCP 已安装,**Claude Code 需要重启加载 MCP**,重启后回到本流程继续 Step 5"
  3. 更新 `coding-assistant/tools/99_运行日志/当前状态.md`:阶段状态=等待人工(重启 Claude Code)
  4. 停止推进,等用户重启后说"继续"
- 用户选 [B] → 跳到 Step 6

---

### Step 5 · 授权并读取设计稿

Agent 告知用户:

```
即将调用 [MCP 名称] 读取设计稿。首次调用会弹出 MCP 授权窗口,请选择:
   - "Yes, and don't ask again" — 永久授权,后续无需重复确认
   - "Yes" — 仅本次授权

授权后我会:
  1. 调用 MCP 读取设计稿元数据(页面/图层/组件树)
  2. 提取 design tokens(色值/字号/间距/圆角)
  3. 抽取关键页面截图供视觉对照
  4. 输出"设计稿解析报告",作为编码输入
```

**Agent 执行:**

1. 调用 MCP 对应工具(以本工程内置 `calicat` MCP 为例):
   - `get_meta_data` 拿文件元信息
   - `get_design_data` 拿图层/组件结构
   - `get_screenshots` 拿关键页面截图
   - `get_interaction_design_data`(如有)拿交互稿数据
2. 将解析结果写入 `coding-assistant/tools/01_需求输入/设计稿解析-[日期].md`,内容包括:
   - 平台 / 文件 ID / 页面列表
   - Design tokens 清单(色板 / 字号 / 间距 / 圆角)
   - 组件树摘要
   - 截图引用(本地缓存路径或链接)
3. 将"数据源类型 = MCP 直读"标记到 [当前状态.md](coding-assistant/tools/99_运行日志/当前状态.md)
4. **跳到 Step 7 进入正式编码**

> 调用失败时,告知用户失败原因,使用 `AskUserQuestion` 让用户选择:[A] 重试 / [B] 改用截图参照(跳 Step 6)。

---

### Step 6 · 截图参照模式(降级路径)

适用于:无 MCP / MCP 不可用 / 用户选择跳过 MCP。

Agent 告知用户:

```
进入"截图参照模式"。请将设计稿关键页面截图(PNG/JPG)放入:
  coding-assistant/tools/01_需求输入/设计稿截图/

建议截图覆盖:
  · 每个独立页面 1 张(整体布局)
  · 关键交互态(hover/active/disabled)各 1 张
  · 复杂组件特写(数据卡片/图表/弹窗)各 1 张

放好后回复"截图已就位",我会按截图视觉对照生成代码。
```

**用户回复后,Agent 执行:**

1. 列出截图文件清单,逐张读取(多模态 LLM 直接读图)
2. 输出"截图解析报告"到 `coding-assistant/tools/01_需求输入/设计稿解析-[日期].md`,标注:
   - 数据源类型 = **截图参照**
   - 已识别页面 / 组件
   - 视觉推断的 token(色值取色器估值 + 间距像素估值)
   - **不确定项清单**(MCP 直读模式下能精确读到、截图模式只能推测的内容)
3. 将"数据源类型 = 截图参照"标记到 [当前状态.md](coding-assistant/tools/99_运行日志/当前状态.md)
4. **进入 Step 7 正式编码**,代码生成时明确标注哪些 token 是"截图推断"以便后续校对

> 截图模式的不确定项必须在 SOP-08 走查阶段由人工逐项核对原稿,确认无视觉偏差。

---

### Step 7 · 进入正式编码

Agent 输出汇总,进入 SOP-06 主流程:

```
═══════════════════════════════════════════
  场景 A-前端 预编码 · 设计稿源确认完成
═══════════════════════════════════════════

数据源类型:[MCP 直读 / 截图参照]
平台:[Calicat / MasterGo / Figma / 截图]
输入文件:coding-assistant/tools/01_需求输入/设计稿解析-[日期].md
不确定项:[N 条](已记录,SOP-08 走查时人工核对)

下一步:进入 SOP-06 编码主流程(TDD 红绿循环)
```

## 红线

- 用户未选完 Step 1~6 之前,**Agent 不得直接进入 TDD 编码**
- MCP 安装命令参数不得猜测,以官方文档或用户提供为准
- 截图参照模式下,代码注释应标注"token 来自截图推断"——便于 SOP-08 人工核对
- MCP 调用失败不可自动降级到"瞎写"模式,必须显式询问用户走截图路径
- 即便走 MCP 直读,SOP-08 走查仍需对照原稿(MCP 解析可能丢失视觉细节)
