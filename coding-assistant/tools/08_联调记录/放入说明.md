# 联调记录

> 分离架构 / 跨模块出错的联调调试记录存放于此。

## 联调四阶段

| 阶段 | 动作 | 目标 |
|---|---|---|
| 1 根因调查 | 读错误信息 / 复现 / 看最近改动 / 加诊断日志 | 找出 WHAT 和 WHY |
| 2 模式分析 | 找类似的工作示例对比 | 列差异 |
| 3 假设验证 | 一次只改一个变量 | 验证或推翻 |
| 4 实施修复 | 写回归测试 → 修复 → 跑通 | 根因修复，不打补丁 |

> ★ **3 次失败质疑架构**——同一问题改 3 次没修好，停下来重新设计。

## 记录命名

`联调记录-[日期].md`
