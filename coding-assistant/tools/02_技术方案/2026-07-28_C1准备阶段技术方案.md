# C1 准备阶段技术方案

> 状态：已基于既有《15_架构纠偏决策V2》《16_一期实施计划与Claude任务包V2》《19_客户演示能力接入与通用语义层并行计划V1》确认；本阶段不改变业务架构。

## 方案

将 C1 拆为两个无文件重叠、无实现依赖的 worktree 子任务：

| 子任务 | 产物 | 写入域 | 作用 |
|---|---|---|---|
| C1-A 能力盘点 | 能力矩阵 | `docs/c1/**` | 证明哪些业务能力确有原系统接口与可追溯字段，为 C1-C 选定唯一可实施的出租房切片。 |
| C1-B 接线测试 | 离线测试与说明 | `tests/**`、`docs/c1/**` | 防止生产模式出现 Adapter 存在但实际不可见、无权或 HTTP 未接通的假可用。 |

## 数据流与安全边界

`用户问题 → 语义计划 → Policy → Tool Registry → Adapter / HTTP Transport → Result / Evidence`

本批次只验证链路完整性与已有源码事实，不改变任何业务数据查询。真实 HTTP、真实数值、统计口径仍作为 C1-C 的单独 Gate。

## 风险与处理

- 原系统接口无法从源码证明：结论必须为“待验证”，不让 Agent 猜测；
- 五层测试为了可离线而使用 Stub：文档必须明确其不代表真实 HTTP 验收；
- 若两个任务都需同一公共测试基础设施，先停止并由 Codex 合并为串行任务，避免 worktree 冲突。
