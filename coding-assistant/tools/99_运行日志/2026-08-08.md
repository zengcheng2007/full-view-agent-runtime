### Run 绑定协议升级（不可变版本 / fail closed）

- `ModelConfigRepository` (协议) 重命名为 `RunModelBindingRepository` 避免与 metadata CRUD 的 `PostgresModelConfigRepository` 撞名；方法签名改为 `store_binding(run_id, ModelConfigSnapshot)` 以携带版本 + 加密 key material。
- `ModelConfigSnapshot` 数据类：`(config_id, config_version, 元数据, api_key_ciphertext, api_key_nonce)`；plaintext key **永远不进 snapshot**，只有 AES-GCM 输出。
- `RunBoundModelPlannerFactory.for_run`：
  - 新 Run → `capture_snapshot_for_runtime()` → `store_binding` → `materialise_snapshot`。
  - Resume → `load_binding` → `load_snapshot`；snapshot 缺失时 **raise** 而不是回退到当前默认（fail closed）。
- `ModelConfigService.capture_snapshot_for_runtime` 通过新加的 `ModelConfigKeyStore.resolve_key_material` 直接读 source row 的 `(ciphertext, nonce)`；in-memory 实现显式 `raise ResourceNotFound`（无 AES cipher 时拒绝静默生成假快照）。
- `ModelConfigService._decrypt` 仅委托给 key store 内部 `_cipher`，加密密钥（进程 secret）不进入 snapshot 数据类。

### 安全不变量（本次改动守住）

1. **Plaintext API key 永不落库**：`run_model_bindings` / `run_model_config_snapshots` 只存 `config_id` + AES-GCM `(ciphertext, nonce)`；加密密钥是进程 secret (`FULL_VIEW_CREDENTIAL_KEY`)，不进 snapshot 数据类。
2. **Immutable binding**：`run_model_bindings` 主键 `run_id`，`ON CONFLICT DO NOTHING`；同 Run 重复绑定不会覆盖原 (config_id, version)。
3. **Immutable snapshot**：`run_model_config_snapshots` 主键 `(config_id, config_version)`，`ON CONFLICT DO NOTHING`；源行被覆盖（同 config_id 升 version / 换 key）不触动旧 snapshot。
4. **Fail closed**：
   - Snapshot 创建失败 → Run 失败（不再静默降级到 base registry）。
   - Binding 存在但 snapshot 缺失 → `RunBoundModelPlannerFactory.for_run` 抛 `RuntimeError`，不回退到当前默认。
   - Key store 不支持 `resolve_key_material`（in-memory）→ `capture_snapshot_for_runtime` 返回 None，不生成假 snapshot。
   - Capability rebuild 时某 pinned 版本已不在 repository → 返回 None，Run 失败（不静默用 live 集合）。
5. **First-write-wins for bindings**：Run 一旦绑定就固定；后续 `resolve_for_runtime` 返回新 config 不影响已绑定 Run。
